# Подсветка козырька — электросхема

Одно гнездо USB-C питает всё: зарядку Kindle, Arduino Nano, энкодер и подсветку из трёх COB-нитей. Энкодер через Nano крутит яркость до полной темноты — в v1 больше ничего, без HomeKit (решение 2026-10-19). Прошивка — `src/` (PlatformIO), схема — `schematic.py` → `schematic.svg`.

![Схема](schematic.svg)

## Что куда

| Откуда | Куда | Примечание |
| --- | --- | --- |
| USB-C `V` | шина **+5V** | силовой провод |
| USB-C `G` | шина **GND** | силовой провод |
| USB-C `D+` / `D−` | — | не подключать |
| C1 `+` / `−` | +5V / GND у самого входа | минус — сторона с полосой на корпусе |
| C2 | +5V / GND рядом с C1 | |
| Kindle-кабель: красный (VBUS) | +5V | цвета прозвонить, бывают нестандартные |
| Kindle-кабель: чёрный (GND) | GND | |
| Kindle-кабель: зелёный (D+) + белый (D−) | **друг с другом**, заизолировать | иначе Kindle может решить, что это компьютер, и урезать ток заряда |
| Nano `5V` | +5V | **не VIN** (VIN идёт через стабилизатор, ему нужно ≥ 7 В) |
| Nano `GND` | GND | |
| Энкодер `+` / `GND` | Nano `5V` / `GND` | |
| Энкодер `CLK` / `DT` / `SW` | Nano `D2` / `D3` / `D4` | D2 и D3 — прерывания |
| Nano `D9` | R1 220 Ом → затвор Q1 (ножка 1) | ШИМ |
| R2 10 кОм | затвор Q1 ↔ +5V | держит лампу выключенной, пока Nano грузится или прошивается |
| Q1 исток (ножка 2) | +5V | силовой провод |
| Q1 сток (ножка 3) | **LAMP+** | |
| LAMP+ | R3 / R4 / R5 6,8 Ом 2 Вт → провод к козырьку → «+» нити 1 / 2 / 3 | по резистору на каждую нить |
| «−» всех нитей | вместе в козырьке → провод → GND | |

Q1 = AO3401, P-канал, ключ по плюсу: `D9` LOW — свет, HIGH — темно.

## Почему так

- **Nano + AO3401, а не RP2040-Zero** (2026-11-23). Сначала выбрали Zero: ШИМ у RP2040 точнее, и затухание внизу плавнее. Но логика у неё 3,3 В, а AO3401 по плюсу от 3,3 В не закрывается — нужен N-канальный AO3400A (или Si2302 / IRLML2502 / IRLML6344), а его не оказалось в Радіомаге. Nano + AO3401 собирается целиком из запасов. Версия под Zero (схема, прошивка, README) — коммит `04c5969` в истории: вернуться, если появится AO3400A и захочется плавнее низ.
- **C1 100 мкФ, а не 1000.** Бросок тока на зарядку 1000 мкФ умный USB-C зарядник принимает за перегрузку и уходит в защиту — пуск-отбой раз в секунду (проверено в `nfc-figurines`).
- **Резисторы 2 Вт.** На 100 % каждый рассеивает 0,6 Вт в закрытом PETG; 1-ваттный на 60 % нагрузки греется, по оценке, до 80–100 °C, а PETG размягчается около 80 °C.

## Развязка по питанию

- **Звезда от входа.** USB-C → короткими толстыми проводами на перфборд, там C1, C2 и две шины +5V / GND. От шин — **отдельные пары** к Kindle, к Nano (энкодер питается от пинов Nano) и к лампе. Импульсный ток ШИМ лампы (до 0,9 А на трёх нитях) тогда не течёт по проводам Nano и Kindle. Общий минус нитей — прямо на GND у входа, не через пин Nano.
- **C1 100 мкФ + C2 0,1 мкФ у входа** сглаживают импульсы ШИМ, не роняя зарядник в защиту.
- **R1 220 Ом** в затвор — ограничивает бросок тока из пина и звон на фронтах.
- **R2 10 кОм** затвор → +5V — без неё при старте Nano пин висит в воздухе и лампа может вспыхнуть.
- Скачет энкодер — по 10 нФ с `CLK` и `DT` на GND (аппаратный антидребезг); прошивка и так отбрасывает невозможные переходы.
- Nano, Q1, C1, C2 и резисторы R1–R5 — на перфборде в базе. К козырьку — 4 провода: «+» каждой нити (уже после её резистора) и общий минус.
- Силовые линии (вход → шины, Kindle, исток Q1, лампа) — 0,35–0,5 мм²; сигнальные — 0,14 мм².

## Ток и тепло

| Потребитель | Ток |
| --- | --- |
| Kindle (заряд) | ≤ ~0,5 А (оценка) |
| Nano + энкодер | ~0,03 А |
| COB-нить на 100 % | 0,3 А каждая |
| **Итого** | 3 нити ~1,45 А — зарядки 5 В 2 А хватает; с запасом — USB-C PD 20 Вт (5 В 3 А) |

Резистор: (5 − 3 В) / 0,3 А ≈ 6,7 → **6,8 Ом**; на 100 % греется на 0,6 Вт, поэтому 2 Вт. Нить на 100 % — ещё ~0,9 Вт тепла. Резисторы не прижимать к PETG. Q1 от 5 В на затворе открыт полностью и почти не греется.

## Прошивка

- Код — `src/main.cpp`, PlatformIO, `nanoatmega328` (старый бутлоадер; «not in sync» — `-e nano_new`).
- Ручка — как обычный диммер: 0 — темно, дальше 48 шагов до 100 %. Шаг — постоянный множитель яркости (~13 %); внизу, где 10-битного ШИМ на это не хватает, — +1 такт на шаг. Вниз до упора — лампа гаснет; вверх из темноты — зажигается с минимума.
- Клик — выключить / включить на последнем уровне, плавно (0,4 с).
- ШИМ на `D9` — Timer1, Fast PWM 10 бит, 15,6 кГц (не пищит, не мерцает на камеру), инверсный режим (P-канал). Выкл — ШИМ отключается, `D9` держится в HIGH: иначе инверсный ШИМ оставляет импульс в 1 такт и нить тлеет.
- Первый шаг — `MIN_DUTY` (3 такта по 62,5 нс). Подобрать на стенде — первый шаг должен еле тлеть.
- Энкодер — свой декодер на прерываниях D2/D3: невозможные переходы (дребезг) отбрасываются, щелчок засчитывается в положении фиксатора. Крутится наоборот — `DIRECTION = -1`.
- Уровень — в EEPROM через 5 с после последнего поворота: переживает отключение питания и не изнашивает EEPROM.
- Заливка из этой папки: `~/.platformio/penv/bin/pio run -t upload && ~/.platformio/penv/bin/pio device monitor`.
- ⚠️ **Пока Nano на стенде — прошивай как угодно. Когда она впаяна в шину — только при воткнутом основном USB-C.** Иначе мак через диод Nano питает всю шину: зарядку Kindle и лампу (до ~1,4 А с порта). Проще всего прошить новую версию до пайки и дальше не трогать.

## Проверить до пайки

- [ ] USB-C платка — кабель C→C от зарядки → на `V`–`G` 5 В
- [ ] Kindle-кабель — прозвонить жилы до пинов micro-USB (1 VBUS, 2 D−, 3 D+, 5 GND), жил 4
- [ ] Полярность нити: 5 В → 220 Ом → нить; тлеет — правильно (обратная полярность через резистор не вредит)
- [ ] AO3401 прозвонкой диода: красный щуп на ножку 3 (сток), чёрный на 2 (исток) → ~0,6–0,7 В
- [ ] Энкодер: между `+` и `CLK` / `DT` ~10 кОм (подтяжки на плате есть)
- [ ] Ток одной нити на 100 % — 0,25–0,3 А (мультиметр в разрыв); больше — поставить 8,2 Ом
- [ ] Зарядник воткнуть ~20 раз — каждый раз стартует, без «пуск-отбой»
- [ ] Час на 100 % — резисторы и козырёк трогаются рукой
- [ ] Kindle на шине заряжается: `ssh kindle 'gasgauge-info -c'` держится или растёт

## Механика

- Гнездо USB-C — в печатном кармане: усилие втыкания держит корпус, а не пайка.
- Пайки на выводах нитей — под термоусадку и каплю клея, чтобы провод не гнул FPC.
